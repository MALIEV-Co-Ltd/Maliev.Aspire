# Production error logging

`AddServiceDefaults` owns one production console log sink. GKE receives single-line JSON with recognized `WARNING`, `ERROR` and `CRITICAL` severity, UTC time, service/deployment version, logger/event, exception types/source method, and validated trace identifiers. Arbitrary logger messages, payload/state values, request URLs, query strings, cookies, customer identifiers and exception text are excluded. Development/Testing retain their existing diagnostic providers; OTLP tracing and metrics remain available in production without duplicating logs to OTLP.

Routine Information/Debug logs and warning-level Polly retry attempts stay quiet. Real EF command errors remain visible without SQL text. Returned terminal dependency 5xx, network failures and timeouts are captured outside the retry pipeline using the actual configured client name. Client aborts and host shutdown cancellations stay quiet. Request exceptions preserve existing status/response contracts, with server failures recorded as ERROR. Explicit handled 5xx responses are recorded too. Failed health probes are bounded to first occurrence and once per five minutes until recovery; successful probes remain quiet.

`UseStandardMiddleware` installs the error boundary and private observability diagnostic before forwarded-header rewriting. Direct loopback GET `/internal/diagnostics/observability` requires a GUID in `X-Maliev-Diagnostic-Id`; public access, spoofed proxy headers, malformed nonces and write methods are denied. An accepted request emits exactly three synthetic records through the actual warning/error/critical logging path and returns expected HTTP 500 with the diagnostic nonce. The process rate limit is one proof per minute; the operational budget is one proof per serving pod per daily run. Never exercise a business endpoint to obtain this evidence. Require matching pod/image/nonce/time records in stdout and Cloud Logging before declaring ingestion verified.

The controlled exception is exactly `Maliev.Diagnostics.ProductionObservabilityDiagnosticException`. Synthetic classification requires the validated nonce and explicit synthetic marker, or the exact `ObservabilityPipelineProbe` warning marker. A generic synthetic flag must not hide business errors.

The new package must be published through the validated immutable package workflow and rebuilt into consumers before these changes reach deployed applications. Audit found ten services pinning older ServiceDefaults packages; they need an explicit version update to the published artifact. A local project-reference test is not proof that a deployed container consumes this code. Bootstrap log factories created before `AddServiceDefaults` must call `Maliev.Diagnostics.ProductionLoggerFactory.CreateBootstrapLogger()` rather than using plaintext exception output. Incoming request aborts and host shutdown remain quiet; a canceled outgoing worker token alone cannot establish a harmless caller abort, so that ambiguous failure is retained for diagnosis. No sink, retention, exclusion, IAM or provider policy changes are required.
